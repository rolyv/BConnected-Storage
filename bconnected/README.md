# BConnected group storage

Personal fork for the Belen alumni pilot. The `BConnectedStorageLauncher` selects native PostgreSQL and the approved 10,000-member cap. The inherited validator still enforces actual/invited-member counts and checks pending approvals and banned members separately. An 8,000-member end-to-end load test remains required.

`migrations/001-postgres.sql` creates four isolated `group_storage` tables for encrypted group state, signed group history, account storage manifests and encrypted items. PostgreSQL combines group state/history writes and manifest/item/clear-all writes into atomic transactions. The original Bigtable implementation remains available under its legacy configuration; the PostgreSQL pilot does not construct Bigtable or S3 signing configuration. Group avatar upload is explicitly unavailable in this mode until a private GCS capability is implemented.

The mounted runtime bundle supplies owned libsignal server parameters and shared authentication keys. The port preserves encrypted protobuf encodings, libsignal authentication, signed changes and group-send endorsements; it uses libsignal-server 0.101.2. The launcher writes no secret values to logs and accepts no command-line secrets. See `BConnectedStorageLauncher` for environment configuration; `group-capacity.yaml` alone remains an incomplete legacy configuration fragment.

The focused package suite passed 230 tests, including 16 real PostgreSQL transaction/concurrency tests and existing cryptographic/controller regressions. A real local HTTP startup using the owned parameter bundle passed health/readiness and authentication checks. The first private Cloud Run revision also passed nine runtime/IAM/read-only API checks using the dedicated groups identity and Cloud SQL IAM proxy. Exact cloud deployment evidence and remaining client/capacity work are recorded separately in the parent workspace's `docs/group-storage.md` and `infra/groups-deployment.json`.

Encrypted group membership stays with Signal's group system. The directory sidecar stores only voluntarily submitted, admin-approved listing metadata, never private groups or message plaintext. Native storage does not itself enforce alumni admission or establish directory proof of group-admin control.
